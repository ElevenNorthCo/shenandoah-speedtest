# Shenandoah Valley Speed Test SEO Audit

Audit date: August 12, 2026  
Search Console window: May 22–August 10, 2026  
Property: `shenandoahspeedtest.com`

## Executive summary

The site is crawlable and its core technical SEO is stronger than its current search traffic suggests. The production build generates static HTML for public routes, uses a consistent `www` canonical, exposes a large crawlable town directory, emits structured data, and keeps private/dashboard routes out of the index.

The immediate problem is not a hidden-page failure. It is a combination of very low authority, little query history, thin/templated community pages before they accumulate data, and a temporary host redirect that leaves Google with more canonical uncertainty than necessary.

The best first content target is **“shentel speed test.”** It is the only query visible in the supplied Search Console export. A new independent guide now directly answers that search intent, provides original diagrams, links to local town pages, cites official sources, and sends readers into the speed-test tool.

## Technical SEO audit

### Passing

- Public routes are generated as static HTML, so Google receives meaningful headings, copy, links, and metadata without waiting for client-side rendering.
- The build currently generates 161 canonical, indexable URLs and two `noindex` routes.
- Public sitemap URLs have unique titles, descriptions, canonicals, robots directives, and one H1 in the generated HTML.
- `/dashboard` and `/404` are excluded from the sitemap and emit `noindex` metadata.
- `robots.txt` allows crawling and advertises the canonical sitemap.
- The `www` host is used consistently in canonicals, the sitemap, Open Graph URLs, and JSON-LD.
- The site has crawlable navigation from the homepage to the guide hub, town directory, and individual communities.
- Google search discovery confirms that the homepage, town directory, individual town pages, and at least one broadband article are indexable.
- Article, breadcrumb, website, web application, place, and FAQ structured data are generated where appropriate.
- Direct clean URLs are built as real HTML files rather than relying on a catch-all SPA rewrite.

### High-priority issue fixed in this change

The live bare domain returned a **307 temporary redirect** to `www`. The Search Console export also attributed its visible pages to non-`www` URLs, while the repository and Google search results use `www` canonicals. That does not prove duplicate indexing, but a temporary redirect is weaker and less explicit than a permanent canonical-host redirect.

`vercel.json` now defines a host-based permanent redirect from every non-`www` path to the equivalent `www` path. Vercel's `permanent: true` configuration produces a 308 redirect after deployment.

### Content and authority issues

1. **The site has almost no established search demand yet.** Eight impressions are a discovery signal, not an SEO baseline. More useful local data, links, mentions, and return usage are required.
2. **The town-page footprint is large relative to the amount of unique content.** More than 150 pages share a similar structure. These pages become defensible when they contain real, local measurements, provider observations, and nearby comparisons. Empty pages should not keep multiplying.
3. **Several existing articles use 2025 dates and unsupported precise provider claims.** The old “best providers” article should be fully re-researched and replaced with a 2026 version before its title/date is changed.
4. **An older rural-broadband article used obsolete Form 477 and 25/3 Mbps language.** This change updates it to the FCC Broadband Data Collection system and the current 100/20 Mbps benchmark.
5. **Existing articles did not expose sources.** The article model now supports visible authoritative sources and crawlable inline link groups.
6. **Most articles use the same generic social image.** The new guide has original in-article diagrams, but future flagship posts should also receive article-specific 1200×630 social images.

### Performance observations

The production build succeeds and reports these main compressed assets:

- Main JavaScript: about 121 KB gzip
- Supabase chunk: about 43 KB gzip
- Main CSS: about 3.3 KB gzip
- Cesium is separated from the main application bundle

These build sizes are reasonable for an interactive speed-test application, but the supplied Search Console export does not include Core Web Vitals. A live PageSpeed Insights or Chrome UX Report review is still needed before making a performance claim.

## Recommended 90-day organic growth plan

### First 7 days

1. Deploy this change and verify that `https://shenandoahspeedtest.com/anything` returns a 308 to the same `www` path.
2. Resubmit `https://www.shenandoahspeedtest.com/sitemap.xml` in Search Console.
3. Inspect and request indexing for the new Shentel guide.
4. Share the guide only where it is genuinely useful: local Facebook/community broadband groups, neighborhood groups, realtor networks, and regional technology discussions.
5. Ask early users to run and submit tests. Unique local data is the site's strongest long-term moat.

### First 30 days

1. Rewrite the outdated 2025 provider roundup as a properly sourced 2026 guide. Do not merely change the year.
2. Publish a second intent-matched guide: **“Why Is My Shentel Internet Slow at Night?”** Link it to the new speed-test guide and relevant town pages.
3. Add county/market hub pages for Rockingham, Shenandoah, Page, Warren, Frederick, and Augusta using genuinely unique summaries rather than more templated town pages.
4. Add a visible sample-size note wherever provider rankings or averages appear. Never call a provider “best” from one or two tests.
5. Add a repeat-test workflow that encourages users to test morning and evening and return later.

### Days 31–90

1. Publish a monthly “State of Shenandoah Valley Internet” report only after enough submissions exist to support it.
2. Pitch anonymized county-level findings to local newspapers, radio, county broadband offices, chambers of commerce, and real-estate publications. Earned local links will matter more than producing dozens of generic posts.
3. Review Search Console by query and landing page every 28 days. Prioritize queries with impressions in positions 8–30 and create or improve the page that best matches each intent.
4. Review indexed versus submitted town pages. Improve, consolidate, or temporarily `noindex` empty near-duplicates if Google declines to index them or treats them as low value.
5. Add article-specific social images and author/editorial methodology details to the strongest guides.

## Measurement plan

Use a 28-day rolling comparison once the site has enough volume. Track:

- Non-branded impressions and clicks
- Queries ranking in positions 8–30
- New guide impressions for `shentel speed test` and close variants
- Organic landings to blog and town pages
- Speed tests started and completed from organic landing pages
- Submitted results by town and provider
- Number of town pages with enough real observations to be uniquely useful
- Referring domains from relevant Virginia/local organizations

Do not judge the strategy from CTR or average position while the property remains in single-digit impressions. The first meaningful milestone is sustained weekly impressions across multiple non-branded queries and more than one landing page.
